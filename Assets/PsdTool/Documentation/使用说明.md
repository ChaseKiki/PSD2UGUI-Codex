# PSD → Unity UI 工具使用说明

[简体中文](使用说明.md) | [English](UserGuide.en.md)

版本：2026.10.30-preview.11（团队试用版）

将分层 PSD 转为可编辑的 Unity uGUI Prefab，减少切图、摆放与控件绑定。美术负责设计与常规分组，程序在 Unity 中识别、审核、生成并验收交互。

## 适用场景与团队分工

适合使用 PSD/uGUI、界面较多且改稿频繁的团队。重点减少设计交付、程序拼接和后续迭代的重复工作，不要求美术掌握控件命名协议。

- **美术交付**：普通中文命名、合理分组、独立控件部件、可编辑文字与字体信息；减少额外切图和规则标注，无需搭建 Unity 的 Viewport/Content 等节点。
- **程序落地**：解析 PSD，审核 AI 的类型、归属和分组建议，生成并验收控件，再接业务逻辑；减少逐张摆放、手动搭层级和引用绑定。
- **后续改稿**：复用来源树与输出位置，先预览差异，再按属性锁增量更新，检查脚本、事件和人工调整，减少重复拼接。

便利主要来自带图审核、局部异常处理、可配置资源规则和 MIT 源码可定制性。AI 识别与增量并非独有功能；复杂稿仍需人工修正，目前没有量化节省工时承诺。当前工具界面主要为中文；英文文档保留中文菜单和按钮原名，便于对照。

## 1. 首次安装（程序负责）

已验证环境：Windows、Unity 2022.3.62f3c1。其他 Unity 版本尚未验证。

1. 项目先安装 uGUI、TextMeshPro；本轮验证版本分别为 1.0.0、3.0.7。
2. 通过 Assets → Import Package → Custom Package 导入本包。
3. 执行 Window → TextMeshPro → Import TMP Essential Resources。
4. 打开 **Tools → PSD 工具 → 打开工具**。首次打开自动生成 `Assets/PsdTool/PsdToolSettings.asset`，不携带原项目配置；同菜单下保留“资源管理”。
5. 选中该配置，设置设计分辨率、输出目录、字体映射。中文文字请使用包含所需汉字的 TMP 字体，默认示例字体不保证中文显示。
6. 如需 AI，点击“Codex 识别”。未安装时窗口提供官方安装指引，安装后点击“已安装，检测并继续”；未登录时点击“登录 ChatGPT”，在浏览器完成授权后自动继续识别。程序同学可协助首次安装。无需 Ollama、本地模型或 API Key，专用 skill 随工具提供。
7. 如需保留图片图层样式，在工具设置面板中选择本机 Photoshop.exe。图片 FX 默认经 Photoshop 临时副本烘焙；没有 Photoshop 时不能保证保留这些效果。不要为跳过报错而直接忽略 FX。

官方 Codex、字体和 Photoshop 不包含在包内。仅登录 ChatGPT 网页不等于 CLI 已登录；工具会检查 CLI 的 ChatGPT 登录状态。自动检测不到时，在识别窗口“高级 / 故障处理”选择官方 `codex.exe`，路径仅存本机。可正常解析 PSD 而不启用 AI，再手工选择控件类型与插槽。

识别统一使用 Codex，不再提供独立 AI 配置窗口、识别方式选择或本地/API 识别按钮。旧配置资产无需重建；旧后端字段仅隐藏保留作序列化兼容，不再控制日常识别入口。

主面板保留解析、预览变更、生成、Codex 识别和场景对比。重建资源索引、审核待删除节点/组件收进“维护与审核”，默认折叠；删除审核仍用于保护增量更新中的人工引用。测试菜单不再对外显示。

## 2. 日常操作

1. 选择 PSD，填写模块名和界面名。建议源 PSD 放在 Assets 外。
2. 点击“解析”，检查节点和预览。
3. 点击 **“Codex 识别”**，等待后台完成；无需复制指令、切换客户端或手动导回。
4. 完成后自动显示识别结果列表。勾选需要应用的控件；不确定或未通过的项按提示核对。未勾选的是识别建议，PSD 的其他视觉节点仍会保留。
5. 点击 **“应用所选并生成 Prefab”**。逐节点绑定明细和诊断入口默认收起，必要时展开“高级”。
6. 验收图片、文字、尺寸、点击热区、勾选、下拉和滚动。
7. 改稿后复用原节点树和输出位置重新解析，先看变更预览，再增量更新。不要为改稿直接删除整个 Prefab。

任务位于当前项目 `Library/PsdTool/CodexTasks/<任务编号>`，包含整图、区域 PNG、元数据和自带 skill，不包含原 PSD、业务代码或账号凭据。Unity 通过官方 `codex exec` 启动只读识别，图片直接附给模型；以结构化 JSON 接收回答，校验通过后才建立控件计划。官方 Codex 自行管理登录与网络，会消耗该账号可用的 Codex 订阅额度，并将图片发送给云端模型。

“识别进度”可重新打开最近任务。关闭进度窗口不终止后台识别；重新打开后自动接收结果。可点击取消，超过 15 分钟会停止等待；Unity 重新编译或退出也会停止本工具启动的任务。失败/取消不会应用控件计划。**即使旧设置开启高置信度自动应用，也需要核对后确认。** 删除 Library 会丢失待接收任务，请重新识别。

自动方式失败时，在“高级 / 故障处理”使用手动模式：复制指令，到官方 Codex 发送任务，完成后自动检测返回文件。手动模式需要任务目录可写，不能绕过客户端权限策略；仍可手动选择返回 JSON。识别窗口默认不展示这些排错按钮。

如需体验首次流程，可在识别窗口高级选项点击“体验新电脑首次配置”：模拟尚未检测到安装，并使用独立的临时登录配置，不修改当前 App 登录。“已安装，检测并继续”可使用这台电脑已有客户端；浏览器授权是真实登录。结束体验也在高级选项中。此模式仅当前 Unity 会话生效，不等于卸载软件或完整重装系统。

来源 PSD、节点树或相关配置变化后，旧结果拒绝导入；错误任务、跨项目、篡改输入图片或 JSON 结构损坏仍拦截整份结果。区域遗漏/重复、类型矛盾、无效部件等只隔离相应建议，保留报告，其余有效建议继续。自动方式只在客户端成功退出且返回完整 JSON 后接收；模型置信度不代表准确率。

结果列表保留所有返回区域，常规已选和历史项默认折叠；待确认与异常优先显示，明确区分可应用、需确认、绑定失败、暂不支持、父控件统一处理和非独立控件。“已应用标记”不代表已生成；“已生成”仍需验收交互。失败/未支持项不会混入可应用项或静默消失。AI 可提议部件插槽、新建虚拟组及同一 PSD 内换父级，均先校验、后审核，不直接修改 PSD。人工决定、属性锁、透明度及剪贴/遮罩/组效果继承受到保护。

## 异常项不阻断其余结果（preview.6）

- 缺项、重复、未知图层及单控件校验失败均列为“需人工处理”。混合控件容器判为 None 时，若同时有完整有效的拆组/绑定方案，会作为可审核建议保留；不再因 None 一概丢弃结构。异常建议不执行，其余有效项照常勾选、应用、生成，保留异常节点的现有配置/视觉。
- 结果窗口可打开“校验报告”，任务目录保存 `校验报告.txt` 与 `review-report.json`。报告含节点路径、类型、状态、原因及本次生成结果。
- 异常项可“定位节点并手动处理”，或人工指定类型后“仅重新校验此区域”；通过后仍需勾选，不自动写入。手动调整节点树后，点击“更多操作 / 绑定明细 → 人工调整后更新校验”，重新验证当前人工配置，不重放原异常 AI 修改；PSD 文件实际改稿仍需重新识别。
- 若确认 AI 建议本就不需要，可“确认忽略此建议（保留现状）”，报告记录已忽略；可恢复为待处理，不会因为全选又自动应用回来。
- 不选 AI 建议时，可以“按现有节点生成（异常稍后处理）”。这不表示异常控件已修复，报告继续保留未处理项。
- 对之前因该错误未导回的完整结果，可在“维护与审核 → 查看最近识别进度 → 高级 / 故障处理”点击“重新校验已有结果（不再请求 AI）”。来源仍需匹配；无需重复花费一次 AI 请求。
- 无法信任整份结果的任务身份/输入损坏，以及源文件不可读、资源写盘失败等环境故障仍会提示，不能伪装成成功。

## 识别结果怎么看（preview.7）

- 主窗口日常流程：**1 解析 PSD → 2 Codex 识别 → 审核待办 → 3 生成 Prefab**。接续旧节点树与项目配置在顶部折叠区；预览变更、场景对比和索引维护放在“维护与审核”。
- 结果上方为统计和生成操作，下方为独立滚动的结果区。异常、人工方案、未勾选项和涉及结构调整的建议优先显示；常规已选、已应用、已忽略与非独立控件默认折叠，可随时展开。
- 折叠只是隐藏显示，不会取消勾选。生成按钮明确显示本次应用的建议数；异常数量另外提示。待办勾选后留在当前位置，避免突然跳行；应用或忽略后归入历史。
- 每项左侧显示识别时的真实 PSD 区域快照及节点路径，右侧集中“定位节点”“重校验此项”“忽略建议”。窄窗口下操作区换行并靠右。
- 点击缩略图打开“PSD 区域定位”：可放大区域，切换整图查看黄色候选框与蓝色涉及图层框，辅助排查跨组部件；也能直接定位 Unity 节点。图片为识别时快照，不是实时 Prefab 截图。旧任务未保存图像或未知返回项会明确提示缺图。
- “更多操作 / 绑定明细”收纳全选、取消、人工修改后的校验更新、报告与诊断入口；不必逐条查看无关的技术绑定数据。
- 资源管理、变更预览、数据迁移与项目配置统一分区。项目设置按输出、字体、识别、控件、贴图、数据和 Photoshop 折叠，日常仅需配置输出与字体。

## 多控件拆组与生成预检（preview.8）

- 同组散放的三个按钮等多个独立控件，外层可以判为 None（不是单个控件），AI 仍可给出多个虚拟控件组与部件归属。校验通过后显示“拆组为 N 个控件”，点击单条右侧“应用此方案”即可建立组并绑定；不需要手动包组，不修改 PSD。只有文字结论而没有完整部件结构，仍不能盲目执行。
- 单条应用只执行该条建议，不会顺带应用其他已勾选项。应用完成后可统一生成 Prefab。
- 结果页预先检查“当前节点 + 已勾选方案”的整体生成结构，显示问题节点、原因和定位入口。改变勾选后更新预检。滚动条方向优先按明确插槽、实际轨道确定，不再被横向装饰撑大的分组误导。
- 可定位到控件的构建/引用错误会局部降级：保留源图层外观，其他有效控件照常生成。结果与报告明确标记“交互待处理”；源节点的类型、插槽与锁不被自动抹除。已有人工/历史组件按增量保护保留，不会为降级直接删除，需单独验收。
- 主窗口生成也使用同一条容错路径，生成后有交互待处理项会展开校验报告。错误的任务身份/来源、损坏的父子结构和资源不可写等问题仍需解决，不能以保存一份无效文件冒充成功。
- 旧识别结果包含完整结构且来源未改变时，可在 Codex 窗口高级菜单“重新校验已有结果”，不必再次请求 AI。已改稿或节点树已变化的任务需重新识别。

## 数据隔离与旧项目迁移

新项目默认持久编辑数据为 `Assets/PsdTool/Editor/Data`（节点树、增量快照、资源登记与索引），运行文字材质为 `Assets/PsdTool/Runtime/Generated/MaterialPresets`，界面图片和 Prefab 仍按配置输出。可重建预览在编辑数据的 `Cache/Previews`；Codex 任务与诊断在项目 Library。不要清理节点树和增量快照来释放缓存空间。

旧项目不自动搬迁。打开“资源管理 → 数据隔离迁移”，先预览，再确认清单。移动保留 .meta/GUID，修复预览路径并更新配置；原 Prefab、脚本事件和运行材质引用继续使用原 GUID。目标冲突或预览后源发生变化会停止，不覆盖合并。生成失败不等于可删除已有输出。

构建前发现旧资源登记等编辑资产仍处于 Resources/StreamingAssets 时，会提示先迁移。运行素材不能输出至 Editor。迁移窗口仅移动登记的工具数据目录和配置的材质目录，不清空整个旧 Data，也不删除未知文件。发布工具包排除编辑数据、生成材质与当前项目输出。

## 3. 美术交付要求

**不用规则命名，中文普通名称即可；仍需合理分组和独立部件。**

- 建议一个控件一个根组；背景、文字、勾选图、箭头、轨道、滑块分别成层。包装组、散图和部分错组可由 AI 提议补组/归属修复，但仍需审核。
- 核心部件尽量直接放在控件根组下，避免无意义的多层包装。
- 文字保留可编辑文字层，提供字体信息；不要求强制栅格化文字。
- 识别时控件整体应可见。隐藏勾选图仍可参与定位，完全隐藏的整组无法可靠看图识别。
- PSD 保存时启用“最大兼容”，让工具读取当前合成预览。
- 提供默认状态说明；多个按下、选中、禁用等相似图层需要程序确认用途。

具体控件：

- **Toggle**：同组直接放底框、勾选图、文字。勾选图在底框内，明显更小，候选尽量唯一。
- **ScrollView**：根组内有独立可视区域底板；长轨道与短滑块分层并处于同组；每个列表项独立成组。标题不要合并进裁剪底板。普通列表保留全部条目，包括沿滚动方向超出视口的条目。
- **Dropdown**：根组直接放顶条背景、当前文字、箭头、展开列表组。列表在顶条下方，与顶条宽度有明确对应；列表组内放底板、轨道、滑块和选项组；选项组按 Toggle 组织。选项不要散放在列表组外。
- **InputField**：同组直接放背景和一层提示文字；输入文字节点可由 Builder 补齐。
- **Button**：支持纯图标、无文字、主副标题及多层背景；装饰和副标题保留，歧义部件不强行指定。
- **Slider / Progress**：线性控件保留独立 track/fill；Slider 还需独立 handle。环形或不明确方向的 Progress 可在待处理项选择填充方式、方向、起点和初始进度，再校验应用；需要独立完整的填充图片，多张候选时应明确 fill 插槽。

美术不用制作 Unity 的 Viewport、Content、Sliding Area 等辅助节点，也不用处理组件引用。九宫与导入参数由程序检查配置。

## 4. 当前功能与边界

工具支持 PSD 节点、图片与文字解析，uGUI Builder，资源目录配置、图片复用、九宫检查、图集、Android/iOS 新资源压缩配置及资源引用/回收管理。增量更新按属性归属和锁定规则保留程序组件、事件与人工修改，仍须检查变更预览。

AI 读取整图、区域图、带编号的图层缩略图和来源层级，返回判型、部件归属和结构建议；Unity 负责来源 ID 白名单、锁定/冲突校验与 Builder 引用。支持 Button、Toggle、ScrollView、Dropdown、InputField 和线性 Slider/Progress；几何规则仍作保守后备，不确定时明确显示失败/待确认。

当前限制：

- 正式输入为**分层 PSD**，不是任意截图；只有一张合成图、缺少独立部件的稿件不能凭空恢复控件。
- 多个相似底图/勾选候选、缺失滑块、跨来源组条目等情况不强行绑定。
- Slider 必须有完整填充和滑块；Progress 可配置横向、纵向、90°/180°/360°径向填充，缺少 fill 或归属歧义仍提示处理。
- 不保证还原所有 Photoshop 效果。图片 FX 需本机 Photoshop；TMP 文字效果仅部分近似还原。
- UI 绑定代码自动生成、通用嵌套 Prefab 自动替换暂未接入。
- 其他操作系统、Unity 版本、多稿泛化准确率与 Android/iOS 真机效果未完成系统验收。

优点：减少规则命名和重复拼接，结果可审核，结构可按项目定制，识别与资源管理、增量更新衔接。

不足：每台电脑需官方 Codex 安装、登录、可用网络与额度；模型仍可能误判，复杂稿需要程序审核；后续维护与回归由团队负责。真实构建验收为 Windows 最小 Player，不代表 Android/iOS 或全部 UI 均已真机验收。

## 5. 项目定位与扩展

本工具面向可审核、可定制的 PSD 到 uGUI 工作流。AI 负责提出控件与结构建议；Unity Builder、来源校验和属性锁负责执行与增量保护。没有多稿准确率或其他产品同稿对比承诺。

固定 Prefab 结构可通过 Builder、人工插槽和生成校验扩展；当前没有仅填写 skill 就生成任意指定结构的通用入口。

## 6. 快速验收与常见问题

- 字体缺失/方框：先导入 TMP 基础资源，再配置覆盖所需汉字的字体及映射。
- Codex 没开始：先检查官方 CLI 是否已安装、登录及有可用网络/额度。日常流程由 Unity 启动 CLI 并接收返回；高级选项可切换手动任务模式。
- Codex 无法读图或写入：用任务目录作为工作目录，通过正常权限审批；必要时重新打开任务。不要将只读环境的“执行结束”当成结果完成。
- 没有自动导回：保持 Unity 任务窗口打开且“自动检测返回结果”开启；检查完整的 `result.json` 是否写在原任务目录，或手工选择返回 JSON。
- 提示任务过期/不匹配：重新导出，不要修改签名、输入图片或混用其他项目结果。
- FX 烘焙失败：检查 Photoshop.exe 配置与错误日志；涉及剪贴/混合依赖时需要程序确认合并策略。
- 控件外观正确但无法交互：检查目标 Graphic、checkmark、template、item、viewport、content、handleRect 等绑定。
- AI 无结果或有歧义：看候选区域和原始返回；先调整分组或手工选择插槽，不依靠反复改名字碰运气。

建议每页至少检查：PSD 对照、Toggle 热区与勾选、Dropdown 展开/选择/收起、ScrollView 滚动，以及改稿后的脚本/事件引用。

工具不读取或转发 ChatGPT/Codex 凭据，不通过 Unity 直接调用订阅接口，不自动操控网页。账号、模型和额度由官方 Codex 管理。升级前提交或备份项目和配置，不要以重新导入工具代替业务数据备份。

按钮热区按正常可见的底图、文字等视觉内容的矩形并集生成，包含包装组内视觉；不因最小点击尺寸扩大按钮，不纳入隐藏图层及 pressed/disabled 状态图。保持视觉图层原位置和大小。已有 Unity 人工锁定的矩形仍受增量保护。

人工/PSD 标记与 AI 建议冲突时，有完整结构方案的待处理项可点击“AI 覆盖并应用此项”。只覆盖该方案涉及的标记；仍校验来源、层级、重复归属与显式锁定。没有完整方案时需重新识别。

工具新建的组使用英文命名，如 ButtonConfirm、Viewport、Content。模型返回中文组名时，生成端按控件/角色与稳定标识生成英文名。PSD 原图层名称和已有人工命名不要求更改。

ScrollRect 的滚动条范围优先采用轨道背景；只有滑块图时，用可视区补全滚动方向长度。Handle 初始大小按可视区与 Content 尺寸计算：空列表或不足一屏铺满轨道，超出一屏则按比例缩小。运行时继续由原生 ScrollRect 更新。程序删除条目后若 Content 的 RectTransform 仍保持原来的大尺寸，仍需同步更新 Content 尺寸，才能反映当前内容量。
